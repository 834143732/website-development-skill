# 网站案例库

`cases/` 是网站案例的唯一入口。所有案例都以同一份人类可读说明和结构化元数据作为基础；有真实归档证据时，再补充可视化复盘页与来源资产。

## 文件契约

每个 `cases/<slug>/` 必须包含：

- `README.md`：记录案例定位、审阅范围、事实、可迁移经验、边界与验收；
- `case.json`：用统一字段记录来源、证据状态、事实、模式与文件清单。

可选增强包括 `index.html`、`assets/source/`，以及在 `case.json` 的 `case_files` 中声明的其他支持文件。未声明的文件不能替代必需的 `README.md` 与 `case.json`。

## 完整度

- `review`：只读审阅档案，允许只有 `README.md + case.json`，适合先沉淀公开页面的观察结论；
- `snapshot`：带真实归档证据的案例快照，除基础文件外，还应包含 `index.html`、`assets/source/` 与相应的文件和资产声明。

新案例可以先从 `review` 开始，不得为了凑齐快照而编造或生成来源资产。只有拿到真实、可追溯的归档证据后，才能升级为 `snapshot`。

## 权利边界

来源网站的 Logo、品牌图形、产品或项目照片、字体、文案、整份 CSS/JavaScript 和其他受保护内容仍归原权利人所有。归档内容只用于内部研究、设计复盘和 AI 上下文；未经授权不得直接用于客户生产项目。

参考站点公开展示的数字、资质、客户、效果或其他主张，不因被记录而成为已核实事实。无法独立核验的内容必须保留其来源位置和未验证状态，不得移植为客户事实或生产文案。

## 新案例步骤

1. 建立 `cases/<slug>/`，先写 `README.md` 与 `case.json`。
2. 按公开页面的实际观察记录事实、未验证项、条件规则和权利边界，不虚构来源资产。
3. 在本索引新增一行，并确认目录名、链接、观察日期与 `artifact_level` 一致。
4. 运行案例库校验。只有真实归档证据、来源映射和支持文件都存在时，才将案例从 `review` 升级为 `snapshot`。

## README 最小模板

```markdown
# 案例名称

## 案例定位

说明行业、受众、页面类型与案例价值。

## 审阅范围

记录来源、观察日期、实际检查的页面、视口与未验证项。

## 已核实事实

只写从公开页面实际观察到的事实，并区分参考站点自己的未验证主张。

## 可迁移经验（条件规则）

写清何时适用、如何使用，以及必须保留的边界。

## 不应直接复制

列出品牌资产、原站实现、未经核实主张及其他不可直接复用内容。

## 复用时的最小验收

列出可观察、可验证的交付检查。

## 归档资源

无归档资源，当前为 review
```
