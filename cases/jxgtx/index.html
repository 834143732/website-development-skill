内容负责解释参数

原站通过 Swiper、Swiper Animate、WOW、CountUp、Hover 与移动菜单形成多层节奏。案例页把它拆成可迁移的实现条件，同时保留静态内容和 reduced-motion 退路。

CHAPTER 01 · HERO

先让现场动作进入视线

Hero 由 5 张 1920×750 图片组成，Swiper 4 秒自动切换、圆点可点击，文字用 fadeInUp 与场景同步。

  • 设备先建立尺度
  • 参数再给证据
  • 按钮承接分类
IMPLEMENTATION

保留节奏，减少历史依赖

新项目可用原生 CSS transition、IntersectionObserver 与单一轮播实现同一阅读节奏；计数、视频和多库动效只在确实提升理解时加载，并提供静态值、poster、键盘和 reduced-motion 方案。

08 / AI INSTRUCTIONS

给 AI 的不是一张设备图，
而是一条交付路径

以下规则适用于光通信、仪器仪表、工业工具与其他“专业参数深、现场任务强”的 B2B 官网。复制决策逻辑，不复制吉星的企业事实和素材。

RULE 01

先展示工作现场，再解释指标

用机房、施工、测试动作建立设备尺度，再通过参数、型号和详情页补足决策证据。

WHEN
技术需要被看见
RULE 02

用任务而不是 SKU 做一级导航

熔接、测试、测量、分配、清洁、工具对应不同工作任务，分类名称要让采购者快速自我定位。

WHEN
产品目录很深
RULE 03

把售后当作第二层产品

手册、快速指南、视频和售后不是页脚补充，而是帮助设备真正被交付和使用的关键入口。

WHEN
安装学习成本高
RULE 04

统计数字要和能力模块绑定

研发、语言、国家、客户四类数字分别对应能力、沟通、网络与影响面，并标注统计口径。

WHEN
需要建立 B2B 信任
RULE 05

动效增强路径，不锁住内容

轮播、hover、CountUp 和移动菜单必须在慢网、键盘、触屏、无脚本与 reduced-motion 下仍然可读可进。

WHEN
首页交互较多
!

DO NOT COPY BLINDLY

不要复制统计、禁用逻辑和旧脚本堆栈

归档素材仅供内部研究；生产项目需取得授权或重新制作。不要照搬 `user-scalable` 限制、anti-copy、CNZZ/Baidu 统计、旧版 jQuery + Swiper + WOW 组合，或将“30+ / 10+ / 50+ / 1000K+”当作其他企业的默认证明。
