# 上海致远绿色能源（ghrepower.com）网站案例

## 案例定位

这是一个面向分布式风电、微电网、离网通讯与新能源投资客户的工业能源官网复盘。案例把原站的五幕全屏叙事、场景化解决方案、产品换景和认证背书提炼为条件规则，供后续网站制作前作为 AI 参考。

- 原站：<https://www.ghrepower.com/>
- 站点名称：上海致远绿色能源股份有限公司（页面标题/author 标记）
- 页面类型：可再生能源 / 分布式风电 / 工业企业官网
- 观察时间：2026-08-23（Asia/Shanghai）
- 观察方式：首页 HTML、CSS、JS、响应头、公开图片与桌面/手机截图的只读观察；未提交表单、未登录、未改变站点状态。
- 案例页：打开同目录的 `index.html`。

## 已核实事实

1. 首页采用纵向全屏 Swiper，共 5 个有效场景；右侧分页显示 `01`–`05`，当前项带短下划线和延伸线。脚本使用 `sessionStorage` 记住所在场景，并启用 `mousewheel: true`。
2. 第一幕内嵌 4 张图的横向 Hero Swiper，自动播放间隔 3 秒、切换速度 1 秒、循环播放。核心主张为“让分布式新能源触手可及”，并提供“观看视频”“探索更多”两个动作。
3. Hero 展示“始于 2006 年”“110+ 自主知识产权”“日本市场份额 50% 以上”三组数字。后两项是企业首页自述，本案例未进行第三方核验。
4. 第二幕用 2 × 2 图片矩阵呈现商业发电、微电网、离网 & 通讯、新能源投资，中心圆持续标识“分布式风电”。卡片 hover 使用橙色到蓝色的渐变遮罩。
5. 第三幕展示 7 个产品系列：FD56、FD42、FD32、FD25、FD22、FD16、FD5/8。鼠标进入系列条带时，jQuery 让对应整屏背景淡入、其他背景淡出。
6. 第四幕以售前与售后两张卡片表达全生命周期运维管理；第五幕左侧包含公司简介、发展历程、企业荣誉和致远文化，右侧用认证图与文字列出 PCT、ClassNK、CE、ETL、G59、CEI0-21、IEC61400 等认证/标准名称。
7. 桌面导航包含关于致远、解决方案、产品介绍、新闻动态、投资者关系、服务中心、联系我们、加入我们，以及 SCADA 和中英日语言入口；移动端改为抽屉导航。
8. 桌面头部初始为半透明深色，移动端改为实体品牌蓝。移动断点隐藏右侧全屏分页，并把产品系列改成两列网格，最后一个入口占满整行。
9. 站点为 WordPress；观察时响应头公开了 `PHP/7.0.30`。页面加载 jQuery 2.1.0、Swiper、AOS、自定义导航与首页脚本。

## 可迁移经验（条件规则）

### 1. 用“品牌 → 方案 → 产品 → 服务 → 证据”组织长决策链

当工业产品同时需要解释行业定位、应用场景、产品族、交付能力和资质时，每一屏只回答一个问题：你是谁、适合我吗、具体有什么、如何交付、凭什么信。章节导航只用于定位；内容本身必须保持自然文档流和可深链访问。

### 2. Hero 先展示行业尺度，再给品牌论点

当真实设备或项目现场能够快速建立可信度时，用强场景图作为第一视觉锚点，HTML 主标题负责价值主张，按钮负责下一步。数字证据应位于第二阅读层级，并附统计时间、口径和来源；不能让营销数字压过用户任务。

### 3. 先按应用场景分流，再进入型号比较

当用户不熟悉型号体系，却知道自己要做商业发电、微电网或离网通讯时，首页按任务建立 4–6 个入口，详情页再解释产品组合。共享能力可放在矩阵中心；超过 6 项时改用分类导航，避免中心图形挤压内容。

### 4. 产品列表负责比较，换景负责记忆

当每个产品系列都有明确的设备或应用图时，可让稳定列表和背景图片同步切换。hover 仅用于预览，点击、聚焦与方向键必须能完成相同操作；名称、关键参数、选型条件和详情链接不能只存在于悬停层。

### 5. 服务与认证放在产品之后完成收束

当用户看过方案和产品后，会自然转向交付风险与合规判断。此时展示售前评估、微观选址、售后响应和技术认证，比在 Hero 中堆一排 Logo 更有说服力。每项承诺、证书和市场数字都要链接到可核验详情。

### 6. 视觉章节感不等于滚轮劫持

桌面端可以用 `scroll-snap`、粘性章节导航或视口高度区块保留“幕”的感觉；移动端使用自然滚动。自动播放、鼠标滚轮、触摸手势和动画都应尊重 `prefers-reduced-motion`，不能成为内容可见的唯一条件。

## 不应直接复制的部分

- 原页 viewport 使用 `maximum-scale=1, user-scalable=no`，会限制用户缩放；新项目应保留浏览器缩放能力，并使用正确的 `lang="zh-CN"`。
- 首页把主内容放进启用 `mousewheel: true` 的全屏 Swiper。新项目不应劫持整页滚轮，也不应让浏览器返回后只依赖 `sessionStorage` 恢复阅读位置。
- 原 CSS 给桌面产品入口统一设置 `width: 20%`，而首页有 7 个系列；这种固定条带宽度在数量变化时容易溢出或压缩，应改用显式网格、可滚动列表或代表系列 + 产品中心。
- 移动 CSS 隐藏售前/售后说明（`.index05 ul li h4`）和关于模块左半部分（`.index04wrap .index04 .left`），造成信息损失；移动适配应重新编排内容，而不是删除关键上下文。
- 首页数字圆环脚本仍访问已经被注释掉的 `myCanvas03`、`myCanvas04`，随后调用 `getContext()`；这是可从归档 HTML 复核的空节点错误风险。组件删除后必须同步清理初始化代码。
- 页面存在 HTTP 的 SCADA/语言链接和百度分享脚本地址，HTTPS 页面可能产生混合内容、跳转安全和第三方依赖问题；生产站应统一 HTTPS 并审查第三方脚本。
- 观察时仍加载 jQuery 2.1.0，响应头还暴露 PHP 7.0.30。新项目不要为复刻交互而继承过时运行时或无必要的版本披露。
- 原站 Logo、图片、CSS、JS 和文案只作内部研究归档；没有授权时不得直接用于客户生产项目。

## 本案例页如何改进原模式

- 保留五幕章节选择器，但页面本身使用自然纵向滚动；无 JavaScript 时默认内容仍可读。
- 产品换景使用原生 JavaScript，并同时支持鼠标、触摸、焦点和方向键。
- 使用正确中文语言标记、可缩放 viewport、跳过导航链接、可见焦点和 `prefers-reduced-motion`。
- 所有企业数字都明确标为“原站自述”，避免 AI 将品牌事实迁移到其他项目。
- 手机端保留三组数字、服务规则和证据边界，不用隐藏文案换取视觉留白。
