05 / MOTION AUDIT

滚动不是炫技，
它要让复杂技术变慢

原站使用 Slick、WOW、CountUp、Lottie、视频固定和滚动进度来建立节奏。案例页把原有节拍拆成可复用的实现条件，并标出性能与无障碍退路。

CHAPTER 01 · HERO

先用家庭与食物讲清“为什么”

Hero 采用淡入切换，桌面端每 10 秒切换一张；可视化圆环与轮播进度同步，图片是主证据，文字保持 HTML 可读。

  • 图片先定情绪
  • 标题再给方向
  • 按钮承接详情
IMPLEMENTATION

保留节奏，减少运行时依赖

新项目可以用原生 IntersectionObserver、CSS transition 和单一轮播实现同一阅读节奏；视频、Lottie 和计数只在确实提升理解时加载，并提供 poster、暂停、静态布局和 reduced-motion 退路。

06 / RESPONSIVE AUDIT

桌面端讲体系，
手机端先保证能滑、能读

原站为 PC 与移动端提供不同 Hero 图片，并在 1200px 以下将产品入口交给 Slick。案例页保留对比证据，同时把移动端不应复制的 viewport 限制标出来。

KEEP

值得复用

  • 消费场景让技术品牌先建立亲和力
  • 产品分类与场景结果绑定
  • 数字条按时间、范围、影响递进

REFINE

  • 移除 user-scalable=no，保留缩放能力

  • 动效依赖应提供无脚本静态内容
  • 统计与分析脚本需要最小化并说明用途

07 / AI INSTRUCTIONS

给 AI 的不是一张家庭照片，
而是一条翻译路径

以下规则适用于生物制造、食品配料、农业科技和其他“技术深、用户广”的企业官网。复制结构，不复制美华的企业事实。

RULE 01

从结果开始，再讲原料

当技术离用户很远时，先用食物、健康、环境或日常动作建立结果感，再进入材料和工艺。

WHEN
技术需要被翻译
RULE 02

用平台词承接多品类

产品入口按采购任务平行展开，每类用一句结果描述，不要把所有型号挤入首屏。

WHEN
产品跨度较大
RULE 03

数字必须有三件套

所有规模数字同时记录单位、统计日期、来源和验证状态；“全球”不是免核验的标签。

WHEN
首页展示规模
RULE 04

把未来方向做成可进入地图

研发领域可以用中心能力与轨道组织，但每个方向都需要详情、阶段或证据，不能只留图形。

WHEN
业务仍在扩张
RULE 05

动效增强，不替代内容

轮播、计数、固定滚动、视频和 Lottie 都应有静态 poster、可暂停操作、键盘状态与 reduced-motion。

WHEN
首页动效较多
!

DO NOT COPY BLINDLY

不要复制 viewport、统计数字和旧脚本

归档素材仅供内部研究；生产项目需取得授权或重新制作。不要照搬 user-scalable=no、WowPop/Google Analytics/Baidu 分析加载、旧版 jQuery + Slick + Lottie 组合，或将“20 年 / 150 个国家 / 30 亿人口”当作其他品牌的默认证明。
