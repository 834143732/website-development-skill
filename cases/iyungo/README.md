# 云中谷工业装备企业站参考拆解

## 审阅范围

- 参考站点：[云中谷智能科技（苏州）有限公司](http://www.iyungo.com/)
- 审阅日期：2026-08-20
- 实际检查页面：[首页](http://www.iyungo.com/)、[产品中心](http://www.iyungo.com/cn/productlist/2-1.html)、[COB 测试台详情](http://www.iyungo.com/cn/product/571.html)
- 实际检查视口：桌面端 1440x900、移动端 390x844
- 分类标签：半导体光芯片测试、工业装备、B2B 企业站、真实设备主视觉、深色科技、全屏楼层叙事、中等内容密度、中英入口
- 未验证项：首页首次导航在 10 秒内未完成等待，但标题和首屏已显示，随后页面达到 `complete`；只能记录为加载风险信号，未定位具体网络或脚本原因。未取得独立控制台日志，运行时错误仍需在实际项目验收中重新检查。
- 本文将页面可见内容视为参考站点自述，不验证合作单位、专利、团队构成、业务覆盖或新闻事实。

## 核心判断

该站最值得借鉴的是用真实大型设备贯穿首屏、产品和方案，并把公司、产品、解决方案、招聘、新闻和底部组织成七个可直接跳转的全屏楼层。它适合产品类别较少、单台价值高、销售依赖技术咨询且拥有高质量设备资产的企业；不适合直接套到型号众多、需要参数筛选或详情证据密集的目录站。

## 值得借鉴

### 真实设备是第一视觉信号

- 首屏每张轮播都把 COC 测试、耦合或老化设备作为画面主体，标题说明设备任务，项目符号补充控制精度、夹具、温控或系统对接等能力。
- 设备实物与业务文案在同一首屏，访客能快速判断“卖什么、解决什么问题”，比只展示芯片、电路或抽象光效更有说服力。
- 复用时应准备统一角度、透明或干净背景的设备图，并控制每帧只表达一个设备或方案；没有真实资产时不宜采用该布局。

### 七屏首页建立清晰品牌节奏

- 桌面端使用固定顶部导航和右侧楼层导航，在一个视口内依次展示首页、关于、产品、方案、招聘、新闻和底部；锚点写入 URL hash，可直接到达对应楼层。
- 每屏只承担一个主题，标题、背景、主体对象和 CTA 数量克制，适合展会后访客、投资或招聘访客快速浏览公司全貌。
- 整屏结构需要保留普通滚动、锚点直达、键盘和减少动效替代，不能让滚轮接管成为访问内容的唯一方式。

### 产品橱窗突出“类别少、单品重”

- 首页产品屏用一个主推设备大图和右侧六类产品缩略导航形成主次关系，既保留品牌画面，又让访客快速看见产品边界。
- 产品中心将 AOI、COB 测试台、老化炉、硅光测试台和机器视觉等七类内容顺序展开，每类包含名称、摘要、产品图和详情入口。
- 审阅时产品中心页面高度约 5030px。该顺序展开模式适合少量高价值设备；当类别或型号超过项目约定阈值，或访客需要跨类别比较时，应改为可筛选网格、比较或搜索，而不是继续拉长叙事列表。

### 产品与解决方案明确分开

- 产品回答“有哪些设备”，解决方案按半导体硅光晶圆测试、光模块与光芯片测试、自动化系统集成、AI 缺陷识别组织“如何完成任务”。
- 首页方案屏用四个一致图标和分区面板快速建立业务地图；每个方案继续连接相关产品时，能同时服务按设备找货和按工艺找方案的访客。
- 数据层应显式维护“方案适用产品”和“产品适用工艺”，不要只在首页写死四个入口。

### 移动端主动改写桌面布局

- 390x844 下首页从全屏楼层改为约 3943px 的自然滚动，文档宽度未超过视口；Hero 缩为横向设备图，解决方案重排为 2x2，新闻改为单列卡片，底部栏目收为手风琴。
- 这种“同一内容、不同编排”的策略比缩小桌面全屏页面更可靠，保留了设备图和主要 CTA。
- 移动端关于区仍把长段文字居中叠在建筑图上，阅读负担明显；复用时应缩短摘要、左对齐正文，并把详细介绍移到内页。

### 企业资产贯穿不同目标

- 关于页屏使用企业建筑，产品屏使用设备，解决方案使用工艺环境，招聘和新闻各有独立场景，能让不同栏目保持主题差异。
- 右下固定入口统一承载客服、消息和返回顶部，桌面端靠视口边缘放置；移动端应合并为不遮挡正文的单一入口或按需隐藏。

## 适用条件

- 客户拥有 3-8 个主要设备类别，单品价值高，转化目标是需求咨询、预约演示或方案沟通。
- 能提供高分辨率设备实拍/渲染、企业建筑或实验室、工艺场景和品牌视觉资产。
- 首页目标是建立品牌与业务全貌，详细参数、文件和案例仍由内页承担。
- 团队能为全屏滚动提供移动端自然流、减少动效、键盘与脚本失败回退，而不是只实现桌面动画。

## 不应照搬

- **产品详情证据不足：** 抽查的 COB 测试台详情只显示产品图、“主要特点”和需求咨询；“主要特点”没有可见内容，“产品详情”区也没有规格、应用、配置、案例或下载。高价值设备详情至少应包含量化参数、功能边界、适用工艺、交付范围和证据资产。
- **语义标题缺失：** 首页可见的公司、产品和新闻大标题主要由普通容器呈现，语义标题只抽查到四个方案 H2；产品中心和 COB 详情未抽查到有效 `h1`-`h6`。每页应有唯一 H1，章节标题保持连续层级。
- **移动菜单触发器无语义：** 390px 下 `.m-bm-navbtn` 是普通 `div`，没有 `role`、`tabindex`、`aria-label` 或 `aria-expanded`；菜单打开时页面滚动也未锁定。应使用原生按钮并管理焦点、背景滚动和展开状态。
- **关于区移动端过密：** 长段公司介绍居中覆盖在建筑照片上，单屏文字行数过多且背景细节影响阅读。移动端首页只保留 3-5 行摘要与可信度要点。
- **少量目录模式不可无限扩展：** 产品中心按类别顺序展开适合七类产品，但缺少筛选、搜索、比较和 URL 状态。型号或类别增加后必须更换为数据驱动的目录结构。
- **全屏滚动依赖实现完整度：** 桌面首页 `scrollHeight` 等于单个视口高度，内容通过全屏插件切换；若脚本、滚轮、触摸或锚点异常，后续内容可能不可达。必须提供普通文档流回退。
- **加载风险需复测：** 首次 HTTP 导航未在 10 秒内结束等待，不能据此断言性能原因；项目复用时仍应测量首屏关键资源、LCP、阻塞脚本和第三方请求。
- **替代文本不完整：** 首页 33 个 `img` 中有 9 个空 `alt`。产品、方案和企业资产应描述用途，装饰图才使用空替代文本。

## 复用时的最小验收

- 首页每个楼层都有单一目标、明确标题、真实资产和可达 CTA；右侧楼层导航、顶部导航与 URL hash 保持一致，刷新和后退后仍能恢复位置。
- 1440px 下滚轮、触控板、键盘、楼层点击和快速连续输入都能到达七个区块；关闭 JS 或脚本失败时改为普通纵向文档流。
- 390px 下解除全屏高度与滚动接管，`scrollWidth <= clientWidth`；Hero、2x2 方案、产品入口、新闻卡和底部手风琴没有遮挡或过小触控目标。
- 产品中心在当前类别数量下可扫描；类别或型号达到项目约定阈值后提供搜索、筛选、比较和可恢复 URL，不继续追加超长叙事列表。
- 每个设备详情至少包含真实产品图、3-8 个关键参数、适用工艺、主要特点、交付/定制边界、关联方案、资料或案例证据和咨询 CTA；缺失内容明确标记，不显示空标题。
- 用键盘验证主导航、移动菜单、轮播、楼层导航、产品切换、手风琴和固定入口；检查可访问名称、焦点顺序、Esc、`aria-expanded` 和焦点恢复。
- 检查图片预留尺寸、懒加载、首屏资源、LCP、CLS、控制台与失败媒体；首次导航超时或长时间 `interactive` 必须定位根因后才能交付。
