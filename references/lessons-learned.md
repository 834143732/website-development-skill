- 日期：2026-08-13
  - 项目类型：通用网站
  - 问题：打开项目时如果不及时同步远端版本，可能基于过期代码继续开发；直接 pull 又可能覆盖本地未提交改动或引入未处理分叉。

- 日期：2026-08-13
  - 项目类型：通用网站
  - 问题：`git push` 成功只代表提交已发送到远端，不代表 GitHub Actions 自动部署已经成功；忽略 queued、失败或错误 commit 的 run 会导致误报。
  - 修正：电脑默认使用 GitHub CLI；每次 push 后按当前分支和 commit SHA 定位 Actions run，检查状态、结论和日志，区分进行中、成功和失败等终态。
  - 规则状态：已确认
  - 默认规则：每次 push 后使用 `gh` 检查对应自动部署，只有匹配当前 commit 的 Actions run 成功才确认部署完成。

- 日期：2026-08-13
  - 项目类型：WordPress
  - 问题：客户服务器的 SSH 能连通不代表实际部署用户具备 `rsync` 和 WP-CLI，也不代表 GitHub Actions runner 能访问同一环境；先触发 Actions 可能导致部署中途失败。
  - 修正：Actions 部署前使用本机保存且已确认的对应服务器 SSH 做只读预检，核对主机、用户、环境、指纹，并在实际部署用户下验证 `rsync`、WP-CLI 可执行及版本；同时核对 runner 的 SSH、网络和运行条件。
  - 规则状态：已确认
  - 默认规则：WordPress 客户服务器在自动部署前必须完成 SSH、`rsync` 和 WP-CLI 预检；任一项缺失、不可执行或无法核对时阻止 Actions，不输出敏感凭据。

- 日期：2026-08-14
  - 项目类型：通用网站
  - 问题：带鼠标浮动动效的模块没有统一光标规范，容易与"只有卡片才显示小手"的既有规则脱节，导致可点击区域缺少指针反馈，或纯展示模块因动效误用指针造成误导。
  - 修正：明确凡是带有鼠标浮动动效的模块，鼠标移上去默认显示小手指针（`cursor: pointer`），因为动效本身在暗示该元素可交互；这类模块一般以卡片形式出现，也适用于其他带悬浮反馈的可点击区域；纯展示且无点击行为的模块不得为动效而加小手。
  - 规则状态：已确认
  - 默认规则：带鼠标浮动动效的模块默认显示小手指针；纯展示且无点击行为的模块不加误导指针。
