# 纯前端网站类型

当前没有用户指定的纯前端样例项目；本文件补充与 WordPress、API 项目的边界，作为没有业务服务依赖时的默认参考。

## 识别信号与边界

纯前端项目满足：

- 页面由 HTML/CSS/JS 和构建产物提供，不依赖同仓库业务 API 或 CMS 数据库。
- 内容来自组件、静态 JSON/Markdown、`public/` 或构建时注入的数据。
- 部署目标是静态托管/CDN；服务端只负责文件、SPA fallback、压缩和缓存。
- 联系表单、搜索、登录、评论等需要写入或保密密钥的能力不应伪装成“纯前端已完成”。

如果运行时调用外部 REST/GraphQL/CMS，归入第三方 API；如果仓库包含业务 `server/api` 和数据库，归入自建后端 API；如果 WordPress 负责渲染和内容管理，归入 WordPress。

## 推荐数据流与目录

推荐链路为：

```text
Git 内容/静态数据 → 构建工具 → dist/.output/public → 静态主机/CDN → 浏览器
```

开工时先确认框架的输出目录和路由策略：

- Vite/React/Vue 等通常发布 `dist/`。
- Nuxt 只有在明确配置静态生成时才发布 `.output/public`；默认 Nitro SSR 不是纯前端。
- Next/Astro 等框架要区分静态导出与服务端运行时，不能只看项目名称。
- `public/` 是源码资源目录，通常不等于最终部署目录。

数据、组件和资源尽量保持清晰边界：页面负责组合，组件负责展示，静态数据使用明确 schema，图片/字体通过稳定的资源路径引用。需要频繁更新的内容不要复制到多个组件；要么集中在一个数据文件，要么升级为 CMS/API，而不是继续堆硬编码 fallback。

## 构建与部署

默认流程：

1. 固定 Node 和 lockfile，执行 `npm ci`。
2. 执行项目已有测试、lint/typecheck 和 `npm run build`。
3. 检查输出目录是否包含必需 HTML、JS、CSS、字体、图片和 robots/sitemap。
4. 上传静态产物到 CDN/静态主机；配置 SPA fallback、HTTPS、压缩、缓存和清理旧资源策略。
5. 做真实 URL smoke test，覆盖首页、直接打开的深层路由、刷新、404、移动端资源和表单错误态。

纯前端部署不应注入可被浏览器读取的私钥、数据库密码或 Admin 凭据。所有 `VITE_*`、`PUBLIC_*`、`NUXT_PUBLIC_*` 等变量都应假设会暴露；只有公开配置、资源根地址和功能开关可以放在客户端。

如果 Actions 负责部署，至少让 workflow 执行依赖安装、测试、构建、产物检查和上传，并在失败时保留旧版本。不要把“上传成功”当作“网站可用”；静态主机配置、缓存失效和深层路由 fallback 同样需要验证。

## 常见误判

- 看到 Nuxt/Next 的 `server` 或 `.output/server` 就认为是后端。先确认是否有业务 API handler、数据库和写入逻辑。
- 前端表单 `preventDefault()` 后显示成功提示，却没有网络请求；这只是交互原型，不是已接通业务。
- 使用 `v-html` 或直接插入 CMS/用户数据而没有清洗；即使页面是静态托管，XSS 风险仍在浏览器端。
- 只测试站点根路径，忽略静态主机对 `/about`、`/product/item/1` 等直接访问的 fallback。
- 把构建时环境变量当成运行时 Secret，或把 API 地址写死后再用错误的环境变量覆盖。
- 只看构建通过，不检查资源 base path、缓存版本、图片大小、无障碍和 `prefers-reduced-motion`。

## 实施检查清单

- [ ] 证明项目没有同仓库业务 API、CMS 数据库和必须的服务端密钥。
- [ ] 明确框架、Node 版本、lockfile、构建命令、输出目录和静态主机类型。
- [ ] 检查静态数据 schema、资源路径、base URL、深层路由 fallback、404 和缓存策略。
- [ ] 所有表单、搜索、登录和第三方 SDK 都标记真实能力边界；没有后端就提供明确的未接通状态。
- [ ] 清洗富文本和用户输入；不把任何私钥、数据库密码或后台凭据编译进客户端。
- [ ] Actions 执行测试、lint/typecheck、构建、产物完整性检查和部署后 HTTP smoke test。
- [ ] 覆盖桌面/移动端、键盘焦点、对比度、图片替代文本、reduced-motion 和加载失败状态。
- [ ] 若需求开始依赖实时内容、写入、鉴权或保密计算，重新分类为第三方 API 或自建后端 API。
