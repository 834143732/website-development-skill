## 核心判断

该站最值得借鉴的是把一家技术平台型材料企业的完整商业链压缩成四个可记忆入口：`PHAmily` 负责原料库，`PHAbrary` 负责应用定制，`PHAdustry` 负责产能与制造，`PHA Life` 负责终端商业化。首页先用自然实景建立“绿色材料”直觉，再依次展示材料、方案、产业化和消费合作，四类内页继续承接各自证据。它适合同时拥有材料谱系、跨行业应用、规模化制造和终端合作的合成生物或新材料平台；若企业只有单一产品、缺少真实应用/产线/客户证据，四层命名和长楼层叙事会制造空洞复杂度。

## 值得借鉴

### 用四个品牌化入口解释技术到市场的链路

- `PHAmily -> PHAbrary -> PHAdustry -> PHA Life` 分别对应“有什么材料、如何解决问题、能否稳定制造、最终如何进入生活”，既是导航栏目，也是业务成熟度叙事。
- 首页四条路径并列展示，内页再分别展开材料属性、行业任务、产线能力和联名商品，避免把技术、方案、工厂和消费品混成一个产品列表。
- 可迁移的是四阶段业务模型，而不是英文词缀。实施前应建立 `material -> grade/property -> application -> solution/sample -> production capability -> commercial product/case -> evidence` 关系，并让同一证据从相关入口互相回链。

### 用自然、实验、工厂和生活四类真实场景完成认知递进

- 首屏森林湖泊把“自然友好”变成第一视觉信号；后续使用材料颗粒/微观图形、应用样品、全球布局/发酵产线和联名产品，把抽象技术逐步落到可见对象。
- 这类资产顺序适合公众不熟悉的新材料：先形成价值直觉，再回答材料是什么、能做什么、谁来制造、市场是否采用。
- 客户项目应优先使用自有真实资产，并为每张图登记所有权、拍摄地点、内容角色、裁切版本、替代文本和更新时间；自然风光不能替代产品、样品、工厂或测试证据。

### 原料页同时提供科学分类和采购入口

- PHAmily 先解释 PHA 来源与低碳/亲和/自然降解三个方向，再显示 `P(3HB)`、`P(3HB-co-4HB)`、`P(3HB-co-3HV)`、单体摩尔比例和型号，兼顾科普与熟悉材料的专业用户。
- “产业级 / 科研级 / 认证 / 专利”作为同一材料库的不同证据维度，有利于区分采购、研发和合规任务。
- 复用时产品卡至少要把商品名、化学/技术名称、牌号、关键组成或参数、级别、可售状态、资料版本和询样/采购 CTA 结构化，不能只把参数写进图片。

### 定制方案按客户任务而非组织部门展开

- PHAbrary 用健康医疗、美妆个护、3D 打印、亲肤纤维、净碳包装和净塑食器六个应用入口，先说明行业问题，再给出可能的制品形态。
- 同一页连续展示全部行业，使初次访问者可以快速比较材料的应用广度；桌面端固定二级导航帮助跳转长页。
- 医疗、生物相容、抗菌率、食品接触和环保主张都必须链接测试方法、适用材料/制品、实验室或认证主体、标准、日期和免责声明；场景照片与口号不能充当证据。

### 产业化页用“布局、数字化、模型、产线”建立交付信任

- PHAdustry 先给全球布局，再用工业 4.0 数据、精密发酵模型和北京/宜昌/西部产线逐层证明规模化能力，顺序符合产业客户的风险判断。
- 三条产线分别说明成立/建成年份、合作主体、投资或产能、产品方向和区域作用，比单独放一张厂房大图更容易比较。
- 复用时应区分设计产能、在建产能、已投产产能和实际产量；数字化率、效率提升和大模型能力需记录基线、样本、测量周期与审核角色。

### PHA Life 用真实联名和购买动作验证商业化

- PHA Life 把时装周包袋、淋膜纸杯等合作产品放在品牌故事之后，并给出“了解 / 购买 / 立即购买 / 即将上线”等不同状态，让终端采用不是一句抽象愿景。
- “同样是 PHA，不同样的产品”把材料平台与多个消费品类别连接，适合展示商业化宽度。
- 数据模型需区分概念样品、展览作品、可购买商品、合作案例和即将上线项目；购买链接、库存、适用地区、合作主体和下线状态要持续维护。

### 移动端改为自然长页，但交互降级仍不完整

- 390x844 下首页约 5622px，高度不再被锁定为单一视口；四类内页也都满足根级 `scrollWidth <= clientWidth`，没有把桌面页面整体缩小。
- 桌面完整导航收敛为移动头部，楼层内容按纵向顺序展开，说明移动端没有继续强制 fullPage 分屏。
- 但部分智造信息在语义树中只有图片/隐藏文字，移动菜单也缺少焦点、Esc 与背景锁定。正确的移动降级应同时解决尺寸、内容可读性和输入方式，而不只是取消横向溢出。

## 适用条件

- 企业同时拥有材料/技术平台、多种牌号或性能组合、跨行业应用开发、可说明的产业化能力和真实商业化案例。
- 主要受众横跨研发/材料工程、品牌/产品团队、采购与产业合作方，需要从不同入口理解同一平台。
- 客户能持续维护牌号参数、样品、应用验证、认证/专利范围、产线状态、合作案例和消费产品状态，并能给出审核后的数据口径。
- 项目预算覆盖关系型内容模型、真实影像、图解、桌面/移动编排、静态回退、性能预算、可访问性和多页面回归，而不只是制作长首页动画。
- 品牌命名确实能帮助用户区分业务阶段；若命名需要反复解释，应优先使用直白栏目名称。

## 不应照搬

- **页面没有有效标题大纲：** 抽查首页和四个内页均没有 `h1`-`h6`。首页虽有 `<main>`，四个内页都未抽查到 `<main>`；各页也没有 `<nav>`。可见大字和图解不能替代页面地标与标题层级。
- **页面语言错误：** 中文页统一为 `html lang="en"`，会影响朗读、断词和翻译工具。中文站应使用 `zh-CN`，英文站使用 `en`。
- **图片加载预算偏重：** 首页 DOM 有 84 张图片、1 个自动循环视频，且 84 张图片均未使用原生 `loading="lazy"`；代表性内页的 16-34 张图片同样没有懒加载。轮播克隆节点不等于都已请求，但仍应检查真实网络、首屏优先级、响应式图片和隐藏项预载。
- **脚本和插件职责重叠：** 首页加载 19 个外部脚本，包括两次 51.la、jQuery、WOW、Swiper/Swiper Animate、Waypoints/CountUp、Fancybox、fullPage 和 scrollOverflow。应按组件根节点按需加载，并让轮播、揭示、计数和滚动控制各自只有一个负责人。
- **fullPage 配置存在运行时冲突：** 控制台重复警告 `scrollBar:true`、`autoScrolling:false` 与 `scrollOverflow:true` 互斥；PHA Life 还报告缺少所需的 `scrolloverflow.min.js`。配置冲突在 Firefox、键盘和嵌套滚动中风险更高。
- **控制台重复语法错误：** 首页和四个代表内页每次导航均记录 `SyntaxError: Invalid or unexpected token`。交付前必须定位到具体资源和字符，不能因视觉上仍可用而忽略。
- **减少动效未确认：** 可读取样式未发现 `prefers-reduced-motion`，另有 8 个跨域样式表无法读取。我们的实现必须直接提供减少动效终态，不能依赖参考站是否支持。
- **移动菜单不可访问且未锁定背景：** 触发器为 `div#phone_nav`，没有角色、`tabindex`、可访问名称、`aria-controls` 或 `aria-expanded`；打开后焦点仍在 `body`，Esc 无法关闭，按 PageDown 时页面背景从顶部滚到约 2389px。
- **楼层导航名称无信息：** 右侧 7-9 个圆点的可访问名称只是 `Section 1` 至 `Section 9`。应改为“材料库”“应用方案”“智造产线”等真实章节名称并反映当前项。
- **非语义链接与控件较多：** 首页抽查到 10 个无有效目标或 JavaScript 型链接，整页只有 1 个原生按钮；轮播箭头、楼层点和部分切换主要依赖 `div/span` 加角色或 `tabindex`。应优先使用原生按钮和真实链接。
- **关键信息可能被烘焙进图形：** 移动智造页若干楼层的 `textContent` 有数据和说明，但渲染 `innerText` 为空，画面主要依赖图解。信息图必须提供可见正文、替代描述或等价数据表。
- **证据入口不足：** 抽查页面未发现 PDF/资料下载；原料页的牌号、方案页的抗菌/医疗主张和智造页的效率/产能数字都需要可追溯资料、版本、适用范围和咨询路径。
- **品牌化栏目不适合所有企业：** 四个 `PHA*` 名称建立了统一记忆，但也增加首次理解成本。业务阶段不完整、命名权不稳定或受众更关注快速选型时，应使用直白导航并把品牌语言留在页面内容中。

## 复用时的最小验收

- 先建立“材料/牌号 -> 性能/规格 -> 应用任务 -> 样品/方案 -> 产线/交付 -> 商业产品/案例 -> 证据”关系图；任一入口都能回到相关材料、应用、证据和咨询动作。
- 首页只保留能回答明确问题的章节；楼层导航显示真实业务名称，支持滚轮、触控板、触摸、键盘、hash、前进/后退、刷新恢复和直接跳过。
- 每页有唯一可见 H1、连续标题层级、`header/nav/main/footer` 地标和正确 `lang`；图解、视频、轮播和数据均有文本等价物。
- 原料卡包含牌号、组成/关键参数、级别、状态和资料版本；应用页说明客户问题、适用材料/制品、验证结果与边界；产线数据区分设计、在建、投产和实际产量。
- 所有医疗、抗菌、低碳、降解、食品接触、产能和效率主张记录主体、标准/方法、样本/基线、日期、适用范围、来源与审核状态；未经核实不发布。
- 1440px 下验证首屏轮播、楼层、视频、产品/伙伴轮播、图解和固定联系入口；390px 下使用自然文档流，所有核心正文可见且 `scrollWidth <= clientWidth`。
- 移动菜单使用原生按钮和 `aria-expanded/aria-controls`，支持 Enter/Space/Esc、焦点进入/陷阱/恢复、背景滚动锁定；轮播和楼层控件触控区域约 44x44 CSS px 以上。
- 开启 `prefers-reduced-motion: reduce` 后停止图片缩放、自动轮播、视频自动播放、计数和楼层转场，直接显示每章最终状态；JS、图片、视频或字体失败时保持普通可读页面。
- 为首页和每类代表内页分别检查控制台、失败请求、重复脚本、LCP、CLS、图片请求数、响应式图片、懒加载和第三方统计；不得保留语法错误或互斥滚动配置。
- 商城、订阅、采购、询样和联系入口分别验证成功、校验失败、网络失败、隐私同意和可恢复状态，外部目标明确标记。
